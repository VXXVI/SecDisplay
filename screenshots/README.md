# Windows 控制台乱码截图（2026-11-10）

两张截图来自 Windows 端接收端运行时的终端窗口，由 Mac 侧发起的问题排查提供。两张都是 2346x1222。

## 图片

| 文件 | 内容 |
|---|---|
| `2026-11-10-windows-console-startup-garbled.png` | 接收端启动日志，中文全为乱码，尾部是 `连接失败 10061` 反复重试，下方叠着一个白色的 SecDisplay 窗口 |
| `2026-11-10-windows-console-stats-garbled.png` | 持续出流的统计窗口，满屏乱码统计行（`包 N / 解码 N / Mbps / fps / 光标+N / 输入 N` 的中文标签全部乱码） |

## 现象

日志里中文标签被读成毫无意义的汉字串，典型的 UTF-8 字节被按 GBK（CP936）解码的结果。对照能还原出来的字段：

| 截图里的乱码 | 实际含义 |
|---|---|
| `闃勫姩浠樻儏縺` | 附加延迟 |
| `瑠 g 爐 澶辮触` | 解码失败 |
| `鍏夋爣` / `鍏夋澘` | 光标 |
| `杈撳叆` / `权撽愛` | 输入 |
| `鍖呰` / `闁傚姩` | 包 / 解码 |
| `鍏板€?xx fps` | 峰值 xx fps |
| `杩炴帴澶辫触 10061` | 连接失败 10061 |

数字、单位（Mbps / ms / fps）、括号和 `+N` 都正常，只有中文标签坏了，这与「日志文件本身是 UTF-8，控制台或查看器按 GBK 解码」一致。

## 背景

之前几轮已经处理过同一根因的几处：

- `build.bat` / `check.bat` 缺 `/utf-8` 导致中文源码编译失败（已修）
- `check.bat` 首行 BOM 让 `@echo off` 失效，`chcp 65001` 下中文 `echo` 吃掉后续行（已修）
- 三个遥测 `.ps1` 是 UTF-8 无 BOM + 中文注释，Windows PowerShell 5.1 按 GBK 读会解析失败（已加 BOM）
- `telemetry_win_loop.ps1` 用默认 ANSI 读 UTF-8 日志，中文判据「附加延迟」匹配不上导致静默空跑（已加 `-Encoding UTF8` 与 ASCII 兜底）

这两张截图说明运行时控制台里看到的仍然是乱码。日志写文件用的是 UTF-8，乱码出现在「把日志回显到控制台」或「用某查看器打开」这一步。具体是接收端自己的 `Log()` 控制台输出没设 UTF-8，还是终端（`chcp`）代码页问题，等 Mac 侧把问题描述推过来再定位。
