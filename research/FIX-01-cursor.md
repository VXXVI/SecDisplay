# 鼠标拖影的根因与修复

## 现象

副屏能用，但鼠标指针明显跟不上，拖影严重。其他内容（静态文字、图片）看起来正常。

## 根因

指针被画进了视频流，于是继承了整条管线的延迟和帧率：

```
指针移动 → 系统合成为新画面 → SCK 采集(~5ms) → 编码(~20ms) → 传输 → 解码 → 呈现
```

按 45fps 计算，指针位置每 22ms 才更新一次，端到端约 50ms。
人眼对指针移动极其敏感，50ms + 22ms 的更新间隔就是明显的拖影。

这解释了为什么「画面看着还行，但鼠标很难受」——静态内容的延迟不敏感，
指针是唯一高频、小位移、人眼精确定位的元素。

## 商业方案的做法

它的更新日志里有三条都指向同一件事：

- "New Display Driver to improve mouse input latency"
- "Fixed cursor stuttering during 120 FPS mirrored connections"
- "Fixed cursor sizing issue"

即**硬件光标**：视频流里不带指针，指针位置单独高频传输，客户端本地绘制。
本地绘制的指针不受视频帧率影响，延迟接近零。

## 本项目修复

### 发送端（macOS）

1. `SCStreamConfiguration.showsCursor = false`，视频不再包含指针
2. 新增 `CursorTracker`，以 120Hz 轮询 `CGEvent` 位置
3. 位置换算成相对虚拟屏的像素坐标，变化超过 0.5px 才发包
4. 光标包独立于视频帧，不占用「在途 2 帧」的配额

协议（新增类型 0x03）：

```
[4 字节大端 长度=18][0x03][8 字节时间戳][float32 x][float32 y][uint8 visible]
```

坐标为相对虚拟屏左上角的像素值，大端浮点。

### 接收端（Windows）

1. 收到 0x03 包后缓存坐标
2. 独立线程以 250Hz 轮询，坐标变化时把「视频坐标 → 窗口客户区 → 屏幕坐标」换算后
   调用 `SetCursorPos`
3. `WM_SETCURSOR` 固定返回箭头光标，避免全屏窗口把光标隐藏

Windows 的光标由硬件合成，不受应用帧率影响，所以指针是跟手的。

### 顺带修的

- 增加每显示器 DPI 感知（`SetProcessDpiAwarenessContext`）。不做这步，
  200% 缩放的系统里全屏窗口只有逻辑尺寸，交换链会被系统再缩一次，画面变糊。
- `F11` 或双击切换全屏/窗口，便于随时切回来看日志。
- 新增 `start.bat`：全屏启动（`monitor.bat` 仍是窗口模式，用于排查）。

## 验证

本地模拟接收端统计：

```
视频包 25  光标包 20
最后光标: (1432.0, 106.0, 1)   ← 相对虚拟屏像素坐标
```

发送端统计行新增「光标」计数，静止时几乎不增长（只在位置变化时发）。

## 未做的

- 光标形状（现在是标准箭头，不跟随 Mac 上的 I 型光标、手型光标变化）
- 光标大小缩放（Windows 高 DPI 下可能偏小）
