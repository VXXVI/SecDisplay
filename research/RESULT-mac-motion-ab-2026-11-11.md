## 一、本地实测（tools/latencyclient + tools/motionloader，127.0.0.1 回环）

运动负载下（motionloader 在虚拟屏播 CALayer 动画）：

```
样本 118 帧  用时 2.1s  帧率 55.4 fps
最小 11.60 ms  中位 20.40 ms  p95 105.98 ms
帧间隔: 平均 17.6 ms (约 57 fps)  min 1.5  p50 16.1  p95 32.3  max 141.8 ms
明显停顿(>2倍平均且>40ms) 2 次，占比 1.7%
```

解读：
- `p50 16.1ms` ≈ 60fps 的帧间隔，说明**主体节奏均匀**。
- `p95 32.3ms` = 约 2× p50，即偶有单帧双倍间隔（掉 1 帧），约 5%。
- 停顿 1.7%，属可接受。
- 注意这是**回环**，不含雷电网络；码率仅 0.9Mbps，链路带宽不是瓶颈。

## 二、与 Windows 观测的矛盾

Windows 侧报告「从未观测到 `当前` > 40fps」，而 Mac 侧本地 55~57fps。
两端差 ~15fps。可能来源（按可能性）：
1. Windows 呈现循环（收流/呈现解耦后"只上屏最新帧"）在运动时丢弃/合并了部分帧。
   请检查 `呈现丢帧` 是否在运动时显著增长。
2. Windows 的解码线程与呈现线程之间队列/节流。
3. Windows 侧 `当前 fps` 统计的是**上屏帧**而非**解码帧**，若上屏被节流会显示偏低。
4. 雷电链路（可能性低：0.9Mbps 远低于 20Gbps）。

请 Windows 在运动时同时看 `解码 N(+N)` 与 `上屏 +N` 是否相等；
若 `解码` 到 55 而 `上屏` 只有 40，就是呈现侧丢帧，需要查 present 循环。
