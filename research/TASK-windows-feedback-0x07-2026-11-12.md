## 一、背景

Mac 侧已经能接收并解析 0x07，但 Windows 还没发。现在自适应码率只看 Mac 本地信号，
看不到 Windows 的呈现延迟和丢帧。补上这条反馈后，Phase 2 闭环才成立。

Mac 侧行为：收到 0x07 会在日志打一行 `0x07 反馈: ...`；收不到时各字段为 0，
健康度退回纯本地判断，Phase 1 行为不变。所以 Windows 不发也不影响现有功能。

## 二、包格式（13 字节，全大端）

```
[0]      0x07                    类型
[1..2]   presentP95  u16          呈现延迟 p95，毫秒
[3..4]   sourceP95   u16          源帧间隔 p95，毫秒
[5..6]   decodeFps10 u16          解码帧率 x10（60fps 发 600）
[7..8]   presentDrop u16          本轮呈现丢帧增量
[9..10]  pacedDrop   u16          本轮节拍丢帧增量
[11..12] reserved    u16          置 0
```

与 0x02、0x04 复用同一条控制字节流，直接 `send()` 即可，不要新开连接。

## 三、实现要求

1. **每 2 秒发一次**，与 Mac 侧 RateController 的评估周期对齐
2. `presentDrop` / `pacedDrop` 发**增量**（本轮新增），不是累计值
3. `presentP95` / `sourceP95` 必须取自**同一个 2 秒窗口**，口径一致，Mac 用两者差值估排队
4. `decodeFps10` 用整数放大 10 倍，避免浮点
5. 窗口宽高不要挤进 0x07（定长），建议后续新增 0x08，本轮不做
6. 发送失败要静默跳过，不能影响视频链路

## 四、开关

建议加 `--feedback` 开关，默认关闭：

- 默认关：行为和现在一致，便于 A/B
- 打开后每 2 秒发一次
- 打开前先确认 Mac 跑的是 `91b0b5a` 之后的二进制

## 五、验收

1. Windows 启动时带 `--feedback`
2. Mac 侧日志应出现：

```
0x07 反馈: presentP95=... sourceP95=... decodeFps=... drop=... paced=...
```

3. 发送端统计行里的「在途」「丢弃」不应因反馈而恶化
4. Mac 侧码率调整日志里，健康度应能反映呈现侧负载

## 六、边界

- 不改 0x01/0x03/0x05
- 不新增连接、不改端口
- 不做窗口尺寸包（0x08），留到下一轮
- 反馈关闭时行为必须与当前完全一致
