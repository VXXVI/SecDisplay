# RESULT — 延迟/卡顿仪表盘（latency_dashboard.py）

日期：2026-11-12　作者：子代理（review 复算会话）

## 一句用法

```
python3 tools/latency_dashboard.py --log prototype/mac/logs/sender_20261111_222549.log
```

跟随模式（发端正在跑时）：

```
python3 tools/latency_dashboard.py --follow --interval 5 --with-latencyclient 10
```

## 功能

1. **日志解析**：逐行流式解析 `sender_*.log` 的每 2 秒统计行（采集/峰值 fps/空闲/发送/光标/图像/输入/丢弃/Mbps/在途/采集延迟/编码延迟），以及码率调整事件（网络拥塞下调、健康度下调、良好回升、静止回升）。正则锚定中文字段名，UTF-8 读取，坏行跳过。
2. **延迟统计**：窗口内采集延迟与编码延迟分开的 p50 / p95 / p99 / max / mean。注意日志里每行本身就是 2 秒均值，所以这里是「均值的分位数」。
3. **卡顿检测**（四类事件，带时间戳落表）：
   - 丢帧：`丢弃` 字段窗口内增量 > 0
   - 在途积压：inFlight ≥ 2 的采样
   - 编码延迟高：enc_lat ≥ 阈值（默认 50 ms，`--enc-lat` 可调）
   - 连续低帧率：有发送/光标/图像活动但 2 秒采集增量折算 fps < 阈值（默认 15，`--low-fps` 可调）连续 ≥ 2 个采样窗
4. **输出**：
   - 终端表格：follow 模式下每 `--interval` 秒清屏刷新，显示窗口统计 + 最近事件 + latencyclient 结果
   - CSV：每样本一行（含换算出的 2 秒增量与 fps），默认落 `research/latency_dashboard_<时间戳>.csv`
   - HTML 自包含报告：4 张内联 SVG 折线图（采集延迟、编码延迟、采集帧率、实际码率），卡顿事件红竖线标注，附卡顿事件表、码率调整表；无 CDN 依赖，直接浏览器打开
5. **端到端延迟**（可选）：`--with-latencyclient [SECS] [HOST]` 会先运行 `tools/latencyclient`，从其 stderr 抓取样本帧数、p50、p95、最大值、明显停顿次数，并入终端表格与 HTML 报告。
6. **回放模式**：不带 `--follow` 时读完整个历史日志即出统计、CSV、HTML，适合事后分析。

## 实现要点

- Python 3.9 标准库（argparse / csv / re / glob / subprocess / signal），零第三方依赖。
- 内存安全：逐行 `readline()` 流式读取，不整读文件；样本 deque 每 2 秒一条，长会话也在毫升级。
- 会话重置：日志里时间戳是进程启动后的秒数，若同一文件被追加写入出现时间回跳 > 5 秒，判定为新一次运行，清空统计只报告最新会话（实测 `sender_20261111_222549.log` 就是两次运行追加在同一文件）。
- 语义提示：`采集` 与 `丢弃` 是进程启动以来的累计值，脚本内部先换算成 2 秒增量再算帧率与丢帧率，避免把累计值误当瞬时值。
- Ctrl-C 干净退出：跟随模式 SIGINT 置标志，EOF 等待循环里检查该标志，退出前补写低帧率段收尾并生成 CSV/HTML。

## 已知限制

1. 日志行本身是 2 秒聚合值（均值），无法还原帧级抖动；帧间隔抖动只有 `latencyclient` 能测，本工具的「连续低帧率」是 2 秒粒度的近似。
2. `采集延迟` / `编码延迟` 为 0 表示该 2 秒内没有新帧样本（静止桌面），统计分位数时会跳过这些 0 值；但这也意味着静止时段的延迟数据缺失是正常现象。
3. 窗口帧率依赖两次采样间的 `采集` 累计差值；发送端重启会重置累计值，脚本用时间回跳检测来应对，但如果重启发生在同一秒内（时间戳不回跳）会被误算一次巨大增量，概率极低。
4. `latencyclient` 依赖 9922 端口有存活的发送端；发送端不在跑时该选项会失败并跳过（不影响 CSV/HTML 生成）。
5. HTML 报告无交互（悬停/缩放），超过 600 点的序列按等间隔降采样，超长会话的尖峰可能被降采样吞掉；CSV 保有全量数据。
