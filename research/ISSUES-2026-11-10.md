| 问题 | 提交 | 说明 |
|---|---|---|
| cmd 回显乱码（bat BOM/LF） | `99507f2` | 7 个 bat 统一去 BOM + CRLF，首行 `@echo off` 干净 |
| cmd 控制台统计乱码 | `f7217f4` | `Log()` 控制台输出改 `WriteConsoleW` 宽字符，绕开 CP936；日志文件仍 UTF-8 |

## 鼠标「回不去 macOS」——架构层面，非单点 bug

现象：用户想让鼠标从副屏回到 Mac 主屏，回不去。

定性：当前协议只实现「鼠标在副屏内移动」，没有「跨越屏幕边界回到主屏」的语义。
相关链路（均已核对代码）：

- Mac `CursorTracker.tick`（`ScreenSender.swift:996`）：读 `CGEvent.location`（全局
  桌面坐标），减虚拟屏 `bounds.minX` 得相对坐标 `rx/ry`；`inside = 0<=rx<b.width`。
  鼠标回到内建主屏时 `rx<0` → `inside=false` → 发 `visible=0` 光标包。
- Windows `OnCursorPacket`（`SecDisplayReceiver.cpp:264`）：`if(!visible) return;`
  —— 直接丢弃，`g_cursorX/Y` 保留旧值，光标线程继续按旧坐标 `SetCursorPos`。
- Windows 光标线程（`:1639`）：1 秒让位守卫（本机鼠标动过就不跟随），
  且 `SetCursorPos` 反复把 Windows 光标按在旧位置。
- 输入回传（Mac `InputInjector.handle` `:921`）：Windows 鼠标事件经 `0x04` 发回，
  Mac 用 `CGEvent.mouseMoved` 把光标重放到虚拟屏坐标，又把 Mac 光标拉回副屏。

结果：两端都不放行，Mac 光标被输入回传拉回虚拟屏、Windows 光标钉在旧位置，
体感即「鼠标被困在副屏」。这是设计边界（`research/FIX-01-cursor.md` 已列光标
形状/跨屏为未做项），不是某个判断写反。

要真正解决需协议级改动：Mac 检测鼠标离开虚拟屏时发明确「离开」事件，Windows
释放光标控制权；并加「边界穿越」把物理鼠标在正确的屏幕间交接。工作量较大，
未在本轮改动。

## 鼠标「还是 Windows 指针」——设计使然

`WM_SETCURSOR` 写死 `SetCursor(LoadCursor(nullptr, IDC_ARROW))`
（`SecDisplayReceiver.cpp:1242`）。Mac 端 `showsCursor=false` 把光标从视频剥离，
只发位置（`0x03`），不发光标图像/热点。Windows 本地绘制的永远是标准箭头，
形状不跟随 Mac（I 型/手型等）。要变成 Mac 真实光标需做光标图像传输 + Windows
`CreateIconIndirect` 或 D3D 本地绘制，逆向报告 `REVERSE-DUET-4.0.526.md` 有方案
（`NewCursorImage` / `cursorHotspotX/Y` / `NSCursor.currentSystemCursor`），未实现。

## 全屏 / 分辨率缩放——缺新鲜数据，未定性

代码侧全屏要素齐备：默认 `fullscreen=true`（`:1268`）、
`PER_MONITOR_AWARE_V2` DPI 感知（`:1505`）、`EnumDisplaySettingsW` 取物理分辨率
（`:1552`）、`SetWindowPos(HWND_TOPMOST)` 兜底。

但 GitHub 上所有遥测均来自几小时前一次 `--windowed` 冒烟：
`fullscreen=false`、`client 1440x900`（窗口模式 `ww=sw/2=1440` 正好）。
用户实际全屏故障瞬间无新鲜日志覆盖。

「分辨率怪/要缩放」最可能两种：
1. 运行 `e153f2c` 之前旧 exe（坐标基准还打「自动 2x」）
2. 启动没带对参数落到窗口模式，1440x900 客户区承载 2880x1800 视频（2:1 缩小发糊）

定向修复需要先拿到一次真实全屏运行日志，重点看：
`全屏目标尺寸` / `窗口客户区` / `坐标基准` / `退出方式` 四行数值。
