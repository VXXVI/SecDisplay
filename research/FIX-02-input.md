# 副屏点击错位：根因与修复

## 现象

在 Windows 副屏上点击某个位置，菜单/响应出现在别处。指针看着在 A 点，点击却作用在 B 点。

## 根因

光标方案有设计冲突：我原先在 Windows 端用 `SetCursorPos` 把系统光标
搬到「Mac 当前光标位置」。

- 用户用自己的鼠标往 A 点移动
- 每 4ms 有一个线程把光标拽回 Mac 的当前位置 B
- 用户点击时，落点是 B 而不是 A

同时，Windows 上的点击**从来没有被转发给 Mac**，所以副屏本身是不可操作的。
这两件事叠加，表现就是「点这里，菜单出现在别处」。

## 正确模型

副屏要能操作，必须回传输入事件，而不是搬动本机光标。

```
Windows 鼠标事件 → 换算成虚拟屏像素坐标 → 发给 Mac → Mac 用 CGEvent 重放
```

光标显示则反过来：Mac 光标位置发给 Windows，Windows 在空闲时把本机光标移过去，
让用户看见 Mac 那边的指针在哪。

两者不能同时抢控制权，所以加了让位规则：

> 本机鼠标最近 1 秒内动过，就以用户的鼠标为准，不搬动光标。

## 实现

### 协议（Windows → Mac，新增类型 0x04，固定 12 字节）

```
[0x04][float32 x 大端][float32 y 大端][uint8 buttons][int16 wheel 大端]
```

- x/y 是相对虚拟屏左上角的像素坐标
- buttons: bit0 左键，bit1 右键，bit2 中键
- wheel: 滚动量

### Mac 端

- 控制通道改为**按帧解析**，不再逐字节扫描（二进制里出现 0x02 会误判）
- `InputInjector` 用 `CGEvent` 重放：先 mouseMoved 再按下/抬起，最后处理滚轮
- 需要「辅助功能」权限，缺失时启动会打警告

### Windows 端

- `WM_MOUSEMOVE` / 按键 / `WM_MOUSEWHEEL` 换算成视频坐标后发 0x04
- 窗口客户区 → 视频像素的映射与呈现一致，所以点哪就是哪
- 光标线程增加让位判断

## 需要用户做的一步

macOS 必须授予**辅助功能**权限，否则 `CGEvent` 投递会被系统丢弃：

```
系统设置 → 隐私与安全性 → 辅助功能
勾选运行发送端的终端（Terminal / iTerm / opencode）
```

授权后需要完全退出终端再重开。

## 验证方法

Mac 日志统计行出现「输入 N」，N 随操作增长即为链路通。
点击后 Mac 上对应位置应有响应。
