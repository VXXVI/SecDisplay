# 端到端打通记录

2026-11-08，Mac ↔ Windows 首次在真实硬件上完整跑通。

## 验证环境

```
发送端  MacBook Pro M1 Pro / 16GB / macOS 27.2
接收端  Lenovo Yoga Slim 7 Pro 14IHU5 (82NC) / Windows 11
        屏幕 2880x1800 @ 89Hz，系统 200% 缩放
        显卡 Intel Iris Xe
链路    雷电线直连，20 Gbps，ping 0.88ms，抖动 0.02ms
```

## 链路

```
CGVirtualDisplay 建虚拟屏 (2880x1800)
  → ScreenCaptureKit 抓帧
  → VideoToolbox H.264 硬编（低延迟模式，无 B 帧）
  → AVCC 打包（关键帧带 SPS/PPS）
  → TCP + NODELAY，在途上限 2 帧
  → Media Foundation DXVA 硬解
  → D3D11 VideoProcessor 裁边转 BGRA
  → 交换链 FLIP + ALLOW_TEARING 直显
```

## 实测结果

| 项目 | 数值 |
|---|---|
| 连续收包 | 517 包 / 516 帧解码，零失败 |
| 端到端延迟（同机客户端） | 中位 21.7 ms，p95 28.3 ms |
| 静态桌面帧率 | ~12.5 fps（保活） |
| 静态桌面码率 | 0.6~1.1 Mbps |
| 首帧关键帧延迟 | 65~611 ms |
| 画面比例 | 正确，1808 纹理裁到 1800 行无变形 |

## 这一轮解决的问题

按发现顺序：

1. **接收端从未发送关键帧请求**（常量定义了但没用），导致连上后无 SPS/PPS、黑屏
2. **硬解枚举方式错误**：Windows 的 H.264 硬解不是 "hardware MFT"，
   用 `MFT_ENUM_FLAG_HARDWARE` 反而过滤掉了能 DXVA 的 MSH264DecoderMFT
3. **NV12 输出类型被拒**：1800 不是 16 的倍数，硬解要 2880x1808，需裁边
4. **连接状态竞争**：旧连接的异步 cancelled 回调把新连接误标断开，
   表现为连上后一帧都不发
5. **采集流中断不恢复**：SCK 报 -3815 后永久停止，需主动重建
6. **静止画面关键帧发不出**：没有新帧可编时标志位悬空，改为用最后一帧立即补 IDR
7. **延迟统计恒为 0**：首帧固定偏移被时钟差钳零，改为窗口最小值估计

## 仍然存在的限制

- Windows 端延迟数字是「附加延迟」（相对最快帧），不是绝对值，
  因为两台机器时钟不同步。绝对值以同机实测的 21.7ms 为准。
- 保活重发的是上一帧编码数据，画面完全静止时接收端看到的是静止画面，
  这是预期行为。
- 尚未做的：音频转发、输入回传（键鼠）、镜像模式、多接收端。
