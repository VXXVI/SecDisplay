# Windows 端操作清单

这份文件是给 Windows 那台机器看的。按顺序做，每步都有明确的成功判据。

当前已知环境（Lenovo Yoga Slim 7 Pro 14IHU5 / 82NC）：

```
屏幕        2880 x 1800 @ 89Hz，系统 200% 缩放，逻辑 1440x900
显卡        Intel Iris Xe Graphics
网络        与 Mac 通过雷电线互连，Mac 是 10.10.10.1
```

---

## 第 0 步：同步最新代码

```powershell
cd C:\SecDisplay
git pull
```

**必须做这一步。** 上一次的代码有两个问题已修：

- 硬件解码器枚举方式错误，导致误判「找不到硬解」
- `printf` / `wprintf` 混用，可能引起崩溃

---

## 第 1 步：重新编译

```powershell
cd C:\SecDisplay\prototype\windows
.\build.bat
```

**成功判据**：最后显示「全部编译成功」。

如果没有 Visual Studio，用 MinGW 版本：

```powershell
.\build-mingw.bat
```

---

## 第 2 步：确认硬件解码可用

```powershell
.\SelfCheck.exe
```

**不要带 IP 参数**，这一步只查本地硬件。

**成功判据**：

```
[OK] 支持 H.264 硬件解码（N 个 profile）
[OK] D3D11 视频处理器可用
[OK] 找到 N 个硬件 H.264 解码器
```

如果 `Iris Xe` 那行显示支持 H.264，说明硬件没问题。

---

## 第 3 步：确认网络可达

```powershell
ping 10.10.10.1
```

**成功判据**：延迟 < 1ms，0% 丢包。

---

## 第 4 步：运行接收端

有两种模式，按场景选。

### 4A. 后台监控模式（推荐先用这个）

双击 **`monitor.bat`**。

它做的事：

- 窗口化运行，**不占满全屏**，远程桌面下也能操作
- 自动重连，Mac 端重启后不用手动干预
- 日志写入 `logs\monitor_日期_时间.log`
- 启动后自动实时显示日志

它等价于：

```powershell
.\SecDisplayReceiver.exe 10.10.10.1 9922 2880 1800 --windowed --log logs\monitor.log
```

### 4B. 全屏正式模式

真正当副屏用时用这个：

```powershell
.\SecDisplayReceiver.exe 10.10.10.1 9922 2880 1800
```

**注意**：这是全屏置顶窗口，会盖住整个桌面。

- 按 `Esc` 退出
- 远程连接时，运行前先把任务管理器设为「始终置顶」，万一卡住还能结束进程

### 命令行参数

```
SecDisplayReceiver.exe <IP> <端口> <宽> <高> [选项]

选项：
  --windowed        窗口模式，不占全屏
  --fullscreen      全屏模式（默认）
  --no-reconnect    断线不自动重连
  --log <文件>      同时写入日志文件
```

## 第 5 步：看日志确认关键环节

启动后会依次打印。**这几行决定成败**：

### 5.1 显示适配器选择

```
  跳过显示适配器（无视频解码能力）: <某个虚拟显示器>
  选用显示适配器: Intel(R) Iris(R) Xe Graphics（N 个解码 profile）
```

必须选中 Intel Iris Xe。如果选中的是虚拟显示适配器，说明识别逻辑有问题。

### 5.2 硬解是否启用

```
找到 N 个 H.264 解码器候选
         [0] xxx  (支持 D3D)
         [1] Microsoft H264 Video Decoder MFT
候选 [0] 接受 D3D 管理器，启用 DXVA 硬件解码
解码器就绪 2880x1800（硬件）
```

**`（硬件）` 这两个字是关键。** 如果显示 `（软件）`，2880x1800 会非常卡，需要回报。

### 5.3 连接

```
连接 10.10.10.1:9922 ...
已连接，目标 2880x1800
已请求关键帧（0x02）
```

### 5.4 收到码流

```
已注入 SPS(28) PPS(8)
输出类型已重建，继续解码
```

`输出类型已重建` 出现后，画面应该就在屏幕上。

### 5.5 稳定后的统计

```
包 xxx  解码 xxx(+xx)  120.0 Mbps  延迟 x.x ms  解码失败 0
```

- `解码失败` 应该一直是 0
- `延迟` 在 10~30ms 算正常
- `Mbps` 由内容决定，静态桌面几 Mbps，有动画时上百

---

## 退出

**全屏模式**：按 `Esc`。

**监控模式**：关闭窗口，或按 `Esc`。

如果都无响应：任务管理器 → 找到 `SecDisplayReceiver.exe` → 结束任务。

监控模式下还有日志可以看：

```powershell
Get-Content logs\monitor_*.log -Wait -Tail 30
```

## 出问题时报什么

**把下面这些一次性发出来**，能直接定位：

1. `SelfCheck.exe` 的完整输出
2. 接收端的完整输出（从启动到崩溃/卡住）
3. 如果黑屏，说明日志停在哪一行
4. `ping 10.10.10.1` 的结果

## 常见现象对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志停在前几步就退出 | 编译的是旧版本 | 重新 `git pull` 并编译 |
| 显示「（软件）」解码 | 硬解未生效 | 用 `SelfCheck.exe` 确认 Iris Xe 支持 H.264 |
| 连上了但黑屏 | 没收到关键帧 | 看日志有没有「已请求关键帧（0x02）」和「已注入 SPS」。Mac 端应出现「收到关键帧请求」 |
| 花屏 / 绿屏 | 色彩转换问题 | 记录显卡驱动版本 |
| 帧率很低 | 软件解码 / 资源竞争 | 检查是否误用软件解码 |
| 卡住无法操作 | 全屏窗口抢焦点 | 任务管理器结束进程 |

---

## 注意事项

1. **Duet 和远程控制的虚拟显示器不用禁用**，程序会自动跳过无解码能力的适配器。但它们会占用显卡资源，如果同时有画面在动，可能影响帧率。

2. **远程连接下测的延迟不准。** 远程工具本身有往返延迟，会叠加到观测值上。要测真实延迟，需要在本机前面看。

3. **分辨率必须是 2880x1800。** 这是这台机器的物理像素，改成别的值会导致缩放，文字会糊。
