# Windows 端操作清单

这份文件是给 Windows 那台机器看的。按顺序做，每步都有明确的成功判据。

当前已知环境（Lenovo Yoga Slim 7 Pro 14IHU5 / 82NC）：

```
屏幕        2880 x 1800 @ 89Hz，系统 200% 缩放，逻辑 1440x900
显卡        Intel Iris Xe Graphics
网络        与 Mac 通过雷电线互连，Mac 是 10.10.10.1
```

---

```powershell
cd C:\SecDisplay

```

**必须做这一步。** 上一次的代码有两个问题已修：

- 硬件解码器枚举方式错误，导致误判「找不到硬解」
- `printf` / `wprintf` 混用，可能引起崩溃

## 第 2 步：确认硬件解码可用

```powershell

```

**不要带 IP 参数**，这一步只查本地硬件。

**成功判据**：

```

[OK] D3D11 视频处理器可用
[OK] 找到 N 个硬件 H.264 解码器
```

如果 `Iris Xe` 那行显示支持 H.264，说明硬件没问题。

## 第 4 步：运行接收端

默认就是全屏铺满。按场景选。

### 4A. 带日志的全屏运行（推荐）

双击 **`monitor.bat`**。

它做的事：

- **全屏铺满**（`--fullscreen`），不是窗口化
- 自动重连，Mac 端重启后不用手动干预
- 日志写入 `logs\monitor_日期_时间.log`，启动后自动实时显示
- 早期版本这里写死过 `--windowed`，导致双击永远半屏，已修正

它等价于：

```powershell
.\SecDisplayReceiver.exe 10.10.10.1 9922 2880 1800 --fullscreen --log logs\monitor.log
```

`start.bat` 也是全屏，不实时滚日志；`diag.bat` 全屏跑 20 秒诊断并自动上传脱敏指标。

### 4B. 直接用命令行

```powershell
.\SecDisplayReceiver.exe 10.10.10.1 9922 2880 1800
```

**注意**：全屏置顶窗口会盖住整个桌面。

- 退出：`Ctrl+Alt+Q` 全局热键 / 托盘图标 / `Esc`（详见下方「退出」章节）
- `F11` / 双击 / 托盘菜单 可切换全屏与窗口，切到窗口后桌面露出，直接点 X 也能关
- 远程连接时，运行前先把任务管理器设为「始终置顶」，万一卡住还能结束进程

### 命令行参数

```
SecDisplayReceiver.exe <IP> <端口> <宽> <高> [选项]

选项：
  --windowed        窗口模式，不占全屏
  --fullscreen      全屏模式（默认）
  --vsync           垂直同步呈现（默认，画面均匀）
  --tearing         免同步呈现（延迟最低，可能抖/撕裂）
  --no-reconnect    断线不自动重连
  --log <文件>      同时写入日志文件
  --coord <宽> <高> 显式指定坐标基准（默认对齐命令行 <宽>x<高>）
                     Mac 切到低分辨率档位、或光标/点击错位时才需要
```

坐标基准决定光标显示和点击回传的位置，两端必须一致。默认取命令行的 `<宽>x<高>`（`e153f2c` 起对齐 Mac `CGDisplayBounds` 物理尺寸，不再是物理/2）。

**Mac 切档位时注意**：发送端 `SECDISPLAY_PRESET` 各档分辨率不同，
Windows 端启动参数要同步，否则画面缩放与坐标基准都会错位：

| Mac 档位 | Mac 虚拟屏 | Windows 启动参数 |
|---|---|---|
| sharp / balanced | 2880x1800 | `... 2880 1800`（默认） |
| smooth | 2240x1400 | `... 2240 1400` 或 `... 2880 1800 --coord 2240 1400` |
| fast | 1920x1200 | `... 1920 1200` 或 `... 2880 1800 --coord 1920 1200` |

呈现器已能处理「解码器实际输出尺寸与命令行不一致」：源比显示小则缩放铺满、
源比显示大则裁掉宏块对齐余量，不会越界。但**坐标基准**仍以 `--coord` 为准，
带档位启动或显式 `--coord` 才能保证光标/点击 1:1。

## 第 5 步：看日志确认关键环节

启动后会依次打印。**这几行决定成败**：

### 5.1 显示适配器选择

```
  跳过显示适配器（无视频解码能力）: <某个虚拟显示器>
  选用显示适配器: Intel(R) Iris(R) Xe Graphics（N 个解码 profile）
```

必须选中 Intel Iris Xe。如果选中的是虚拟显示适配器，说明识别逻辑有问题。

### 5.2 硬解是否启用

```
找到 N 个 H.264 解码器候选
         [0] xxx  (支持 D3D)
         [1] Microsoft H264 Video Decoder MFT
候选 [0] 接受 D3D 管理器，启用 DXVA 硬件解码
解码器就绪 2880x1800（硬件）
```

**`（硬件）` 这两个字是关键。** 如果显示 `（软件）`，2880x1800 会非常卡，需要回报。

### 5.3 连接

```
连接 10.10.10.1:9922 ...
已连接，目标 2880x1800
已请求关键帧（0x02）
```

### 5.4 收到码流

```
已注入 SPS(28) PPS(8)
输出类型已重建，继续解码
```

`输出类型已重建` 出现后，画面应该就在屏幕上。

### 5.5 稳定后的统计

```
包 xxx  解码 xxx(+xx)  120.0 Mbps  延迟 x.x ms  解码失败 0
```

- `解码失败` 应该一直是 0
- `延迟` 在 10~30ms 算正常
- `Mbps` 由内容决定，静态桌面几 Mbps，有动画时上百

## 退出

全屏是置顶无边框窗口，会盖住整个桌面。有四种退出方式，按可靠度排：

1. **`Ctrl+Alt+Q` 全局热键**（最稳，不依赖任何可见界面，焦点无关，全屏盖住一切时也能退）
2. **系统托盘小图标**：右键 → 退出 SecDisplay；或左键单击直接退出。托盘在任务栏右下角，窗口切到「窗口模式」后尤其好用。
3. **`Esc`**：接收端窗口有焦点时有效
4. **`F11`**：先切回窗口模式，桌面露出来后点右上角 X 关闭

托盘右键菜单还有「切换全屏 / 窗口」「关于」。

如果这些都没反应（比如焦点被任务管理器抢走、或系统卡死），命令行强杀：

```powershell
taskkill /f /im SecDisplayReceiver.exe
```

`Win+R` 输入上面这条回车即可，不用看见窗口。既往版本只有 Esc 一个出口，出现过「任务管理器被置顶窗口盖住、关不掉」的情况，现已补齐托盘与全局热键。

监控模式下还有日志可以看：

```powershell
Get-Content logs\monitor_*.log -Wait -Tail 30
```

## 出问题时报什么

**把下面这些一次性发出来**，能直接定位：

1. `SelfCheck.exe` 的完整输出
2. 接收端的完整输出（从启动到崩溃/卡住）
3. 如果黑屏，说明日志停在哪一行
4. `ping 10.10.10.1` 的结果

## 常见现象对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志停在前几步就退出 | 编译的是旧版本 | 重新 `git pull` 并编译 |
| 显示「（软件）」解码 | 硬解未生效 | 用 `SelfCheck.exe` 确认 Iris Xe 支持 H.264 |
| 连上了但黑屏 | 没收到关键帧 | 看日志有没有「已请求关键帧（0x02）」和「已注入 SPS」。Mac 端应出现「收到关键帧请求」 |
| 花屏 / 绿屏 | 色彩转换问题 | 记录显卡驱动版本 |
| 帧率很低 | 软件解码 / 资源竞争 | 检查是否误用软件解码 |
| 卡住无法操作 | 全屏窗口抢焦点 | 任务管理器结束进程 |

## 无人值守遥测（可选，装一次即可）

装了之后，接收端带 `--log` 运行时，每 5 分钟自动从日志提取脱敏指标并 push 到 GitHub，不用再手动整理贴日志。

```
cd C:\SecDisplay\prototype\windows
install_telemetry.bat
```

- 只上传数值和固定枚举，不含 IP、主机名、日志正文
- 设备标识用仓库外的随机 ID
- 手动触发：`schtasks /run /tn "SecDisplayTelemetry"`
- 卸载：`install_telemetry.bat remove`
- 前提：接收端带 `--log` 运行（`start.bat` / `monitor.bat` / `diag.bat` 已带），`logs\` 下有日志才有数据

`diag.bat` 跑完也会自动上传一次，不装定时任务也能用这条手动路径。

## 注意事项

1. **Duet 和远程控制的虚拟显示器不用禁用**，程序会自动跳过无解码能力的适配器。但它们会占用显卡资源，如果同时有画面在动，可能影响帧率。

2. **远程连接下测的延迟不准。** 远程工具本身有往返延迟，会叠加到观测值上。要测真实延迟，需要在本机前面看。

3. **分辨率必须是 2880x1800。** 这是这台机器的物理像素，改成别的值会导致缩放，文字会糊。

4. **虚拟屏身份与 Sidecar 共存。** Mac 端虚拟屏用独立 EDID 身份号，采集侧靠它精确选屏，Sidecar 接入/断开不会导致抓错屏。若发现抓到了 iPad 的画面，看 Mac 启动日志的「在线显示器身份」，`[SELF]` 应落在 SecDisplay 上。
