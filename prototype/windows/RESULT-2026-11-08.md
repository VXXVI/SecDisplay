## 卡点：NV12 输出类型被拒

`SetOutputType(NV12 2880x1800)` 返回 **`0xC00D36B4` = MF_E_INVALIDMEDIATYPE**。
输入类型（H.264 + SPS/PPS）已经被接受，只有输出类型被拒。

### 怀疑原因：高度 1800 不是 16 的倍数

H.264 宏块是 16x16，1800 = 16 x 112 + 8。硬解（DXVA / D3D11 Video Decoder）输出的
NV12 表面必须按**编码尺寸对齐**，也就是 2880 x **1808**，再由视频处理器裁掉下面 8 行。
请求 2880x1800 会被解码器判为非法类型；软件解码则不受这个限制。

这个推断还没拿到直接证据，验证方法见下。

### 另一个现象：Mac 只在画面变化时出帧

连续两次 20~45 秒的运行里，收包数分别停在 **9** 和 **1**，之后一直 `0.0 Mbps`。
用官方 `tools/test_keyframe.py`（改成 `HOST=10.10.10.1` 从 Windows 直连，纯 Python、
不解码不开窗）复现同样结果：10 秒内 **0 帧**。

说明 ScreenCaptureKit 抓的是发送端自己创建的虚拟屏，那块屏**没有内容变化就不出帧**。
画面静止时连关键帧都拿不到（0x02 请求只对"下一帧"生效，而没有下一帧）。

对使用者的影响：静止画面下接收端会一直黑屏，哪怕解码链路是好的。

## 建议的两处修改

### 1. 输出类型改成"问解码器要"，不要硬写宽高

```cpp
hr = transform_->SetOutputType(0, out.Get(), 0);
if (FAILED(hr)) {
    // 硬解要求按宏块对齐（1800 -> 1808），或解码器只接受特定子类型
    for (DWORD i = 0; ; ++i) {
        ComPtr<IMFMediaType> avail;
        HRESULT ar = transform_->GetOutputAvailableType(0, i, &avail);
        if (ar == MF_E_NO_MORE_TYPES) break;
        if (FAILED(ar)) break;
        GUID sub{}; avail->GetGUID(MF_MT_SUBTYPE, &sub);
        UINT32 w = 0, h = 0; MFGetAttributeSize(avail.Get(), MF_MT_FRAME_SIZE, &w, &h);
        if (sub == MFVideoFormat_NV12) { out = avail; break; }
    }
    transform_->SetOutputType(0, out.Get(), 0);
}
```

**注意配套改动**：拿到的实际尺寸可能是 2880x1808。`Presenter` 里创建视频处理器时用的是
`width_/height_`（2880x1800），必须把解码器给出的实际输出尺寸传进去，并在
`VideoProcessorSetStreamDestRect` / source rect 里把多余的 8 行裁掉，否则画面会被拉伸。

### 2. 静止画面下没有帧

两个方向，任选：

- 发送端在无变化时**定时重发上一帧**（哪怕内容相同），保证接收端一直有数据；
- 或者接收端把"超过 N 秒没收到包"显示成一个明确的提示，而不是静默黑屏。

## 追加：问题已修复并实测通过

按上面的思路改完后，本机实测：

```
按 2880x1800 设输出类型失败 C00D36B4，改向解码器查询可用类型
  可用输出[0] 子类型 3231564E 尺寸 2880x1808
解码器按 2880x1808 输出（比请求的 2880x1800 高），呈现时裁掉多余行
输出类型已重建，继续解码
呈现器: 输入 2880x1808，只取 2880x1800
包 324  解码 323(+26)  0.6 Mbps  延迟 0.0 ms  解码失败 0
```

**推断得到解码器自己的证实**：NV12 可用输出只有 2880x**1808**，请求 1800 必然被拒。
改完之后连续解码 300+ 帧、`解码失败 0`。

具体改动：

1. `Decoder::SetOutputTypeD3D()`
   - 输入类型未就绪时直接返回，不再产生 `C00D6D60` 噪声
   - 显式设 2880x1800 失败 → `GetOutputAvailableType` 枚举，优先取尺寸完全一致的 NV12，
     否则取第一个 NV12，并打印候选清单
   - 成功后用 `GetOutputCurrentType` 记录实际尺寸，由 `outWidth()/outHeight()` 暴露

2. `Presenter`
   - 新增 `srcW_/srcH_`（解码器实际输出尺寸）与 `SetSourceSize()`，尺寸变化时重建视频处理器
   - 当输入比显示区大时，用 `VideoProcessorSetStreamSourceRect` 只取左上角可见区域，
     避免 1808 被纵向压成 1800
   - 系统内存上传路径的纹理尺寸同步改用 `srcW_/srcH_`

3. 静止画面提示
   - 连续 5 轮（约 10 秒）无新帧时打印一次明确提示，说明是 ScreenCaptureKit 变化驱动导致的，
     而不是链路故障

两套工具链（MSVC 14.44 / MinGW g++ 16.2）均编译通过。
