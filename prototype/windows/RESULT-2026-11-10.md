## 实机验证

命令（窗口化模式，不占全屏，不依赖 Mac 在线）：

```cmd
SecDisplayReceiver.exe 10.10.10.1 9922 2880 1800 --windowed --log logs/tray_smoke.log
```

关键日志：

```
退出方式: Esc / 左键托盘图标 / 右键菜单 / Ctrl+Alt+Q
窗口客户区 1440x900  窗口矩形 1466x971
坐标基准: 逻辑 2880x1800（物理 2880x1800，默认对齐物理）
连接 10.10.10.1:9922 ...
连接失败 10061
```

结论：

- 托盘图标注册成功。日志打出「退出方式」那一行，说明 `TrayCreate` 里的 `Shell_NotifyIconA(NIM_ADD)` 走到了，没有出现「托盘图标添加失败」。
- 全局热键注册成功。没有打出「全局热键 Ctrl+Alt+Q 注册失败」，`RegisterHotKey` 返回有效。
- 窗口化模式正常，`坐标基准` 与 `e153f2c` 的修复一致，默认对齐物理 2880x1800。
- 自动重连正常。Mac 发送端未在 9922 监听，日志按预期循环「连接失败 10061 / 连接 ...」。

统一退出路径：向窗口投递 `WM_CLOSE`，进程干净退出，无残留进程，日志尾部走到「网络循环退出」。`RequestQuit -> WM_CLOSE -> 清托盘/热键/线程` 这条链路在实机上通了。

## 代码审查发现

对 `bcceb45` 新增段（`SecDisplayReceiver.cpp` 约 185-245、1148-1193、1566-1660 行）做了逐行核对。

**一处运行时风险（建议 Mac 侧关注，尚未在已连接态验证）**

退出清理段的顺序是 `TrayRemove -> UnregisterHotKey -> g_alive=false -> net.join()`。`NetworkLoop` 里收流线程阻塞在 `RecvAll` 的 `recv(s, ...)` 上，而 `RecvAll` 没有设置 `SO_RCVTIMEO`，socket 也只在连接断开后才 `shutdown/closesocket`。也就是说，当「已经连上 Mac、正正常收流」时按 `Ctrl+Alt+Q`，消息循环退出、`g_alive` 置 false，但 `net.join()` 可能一直等那个阻塞的 `recv` 返回，进程卡在退出途中。托盘图标此时已经被 `TrayRemove` 摘掉，看起来像「点了退出却没反应」。

本次冒烟测试是在「连接失败 / 自动重连」分支退出的，那一段有 `Sleep(2000)` 且每轮会重新检查 `g_alive`，所以秒退。**已连接态的退出没有覆盖到**，等 Mac 发送端恢复后建议专门复测一次：连上并稳定收流时按 `Ctrl+Alt+Q`，看进程是否在 1 秒内退出。

可行的修法（供参考，未改）：退出时先 `shutdown(g_sock, SD_BOTH)` 让阻塞的 `recv` 立即返回，recv 线程 `connAlive=false` 后 `watch.join()` 也会跟着退出；或给 `RecvAll` 加 `SO_RCVTIMEO` 超时轮询 `g_alive`。

**核查通过、无需改动的部分**

- `NOTIFYICONDATAA` 初始化完整：`cbSize / hWnd / uID / uFlags / uCallbackMessage / hIcon / szTip` 都设了，用 `IDI_APPLICATION` 省资源文件可行。
- `strncpy` 写 `szTip` 后手动补 `'\0'`，无越界，兼容 MinGW 与 MSVC。
- `TrayRemove` 幂等：`g_trayAdded` 标志保证 `NIM_DELETE` 只发一次，`WM_CLOSE` / `WM_DESTROY` / 退出清理段重复调用无害。
- `RegisterHotKey` 与 `UnregisterHotKey` 配对，注册失败时仍调用 `UnregisterHotKey` 是安全的（对未注册 id 返回错误码，无副作用）。
- `HOTKEY_QUIT_ID=1` 与三个 `ID_TRAY_*`（1001/1002/1003）不冲突，窗口类没有菜单资源，无 id 撞车。
- `TrayShowMenu` 有 `CreatePopupMenu / AppendMenuA / SetForegroundWindow / TrackPopupMenu / DestroyMenu` 完整配对，前置激活避免菜单被置顶窗口盖住。
- `RequestQuit` 用 `PostMessageA(g_hwnd, WM_CLOSE)`，窗口销毁后 `g_hwnd` 才可能悬空，但退出路径里 `RequestQuit` 都在消息循环存活期调用，安全。
- `cursorThread` 的 `Sleep(4)` 循环在 `g_alive=false` 后 4ms 内退出，不构成卡顿。

**一处行为提示（非 bug）**

`ID_TRAY_ABOUT` 的 `MessageBoxA` 跑在消息循环线程，弹框期间消息泵被阻塞，托盘和热键暂时无响应，点掉「关于」即恢复。模态框本就如此，符合预期。

## 另修：`start.bat` 去掉 UTF-8 BOM

`start.bat` 是双击全屏入口，文件头带 BOM（`EF BB BF`）。在 GBK 控制台下 cmd 把首行读成 `锘@echo off`，`@echo off` 失效，运行时会逐行回显命令，界面很乱。这和之前 `check.bat` 踩过的是同一个根因。

改动仅去掉 BOM 三个字节，CRLF（29 行）和其余内容不变。用临时副本（占位 exe + 跳过真实启动）完整跑了一遍：`@echo off` 生效，无命令行回显，中文提示正常，退出码 0。
